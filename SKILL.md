# Генерация скелета проекта TIA Portal VCI по образцу и таблице Excel

Навык создаёт структуру папок и исходники VCI для целевого ПЛК: DB/FC технологических групп, механизмы, датчики, привязку DI/DO и `Main`. Вся логика проверена на реальной задаче (PLC_315 → PLC_316, 9 групп, 52 механизма, 32 датчика).

Главный принцип: **из эталона берётся структура, а не текст.** Эталонный ПЛК содержит ошибки копипаста (см. «Ловушки эталона»), их нельзя переносить в результат.

## Шаг 0. Уточни исходные данные (до любой генерации)

Если ответа нет в запросе, спроси один раз, коротко:

1. **Какой ПЛК целевой и какой эталон.** В Excel обычно нет колонки «ПЛК», а карты DI/DO часто лежат только в эталоне. Без вопроса скилл молча клонирует всё в целевой ПЛК, хотя данные могут указывать на эталон.
2. **Все ли агрегаты из Excel относятся к целевому ПЛК** или часть групп остаётся в другом.
3. **Брать ли DI/DO целевого ПЛК из эталона**, если у целевого своей карты нет.
4. **Как сдавать результат:** ZIP, отдельная ветка git, оба варианта.

Затем сам определи по рабочей области:

- `.vci/workspace.vci.config` → `WorkspaceLanguage` (определяет язык `.s7res`).
- `git ls-files --eol` → как репозиторий хранит окончания строк (`i/lf` или `i/crlf`).
- `Types/` в корне репозитория → исходники библиотечных UDT и FB (см. шаг 1).

## Шаг 1. Анализ эталона и библиотечных типов

### Структура эталонного ПЛК

| Папка | Содержимое |
| --- | --- |
| `PLC data types/<библиотека>/` | `.liblink` на UDT |
| `PLC tags/` | `Default tag table.xml` (clock memory, `FirstScan`, `AlwaysTRUE/FALSE`, `___testbool___`), `ConstantReady.xml`, `ModeConstant.xml`, `StateConstant.xml` |
| `Program blocks/0. <библиотека>/` | `.liblink` на FB и исходники `Notice.s7dcl`, `NoticeShow.s7dcl`, `LampPulses.s7dcl` |
| `Program blocks/1. Специальные функции и DB/` | `Hmi.s7dcl` |
| `Program blocks/10. DInput/`, `20. DOutput/` | `DI.s7dcl`, `DO.s7dcl` |
| `Program blocks/<база>. <тип> <агрегат>/` | `G_<агр>`, `FC_<агр>` (+ `.s7res`), подпапки `AI/`, `Units/` |
| `Program blocks/Main.s7dcl` | OB1 с вызовами `FC_<агр>()` |

### Источник определений типов

`.liblink` содержит только GUID, полей в нём нет. Реальные определения UDT и FB лежат в `Types/…/*.s7dcl` в корне репозитория. Читай поля и лимиты оттуда. Если папки `Types/` нет, спроси у пользователя дамп библиотеки.

### Лимиты строковых полей

Литерал `WSTRING#'...'` длиной K имеет тип `WString[K]`; присвоение в поле меньшей длины не скомпилируется.

| Поле | Лимит | Где |
| --- | --- | --- |
| `Settings.Name` (`GroupSettings`, `Drive2DSettings`, `OnOffSettings`, `HmiValveSettings`, `HmiAnalogSensorSettings`) | 30 | группы, механизмы, датчики |
| `BitDescription.Reason`, `UnitFullName.Full` | 70 | причины интерлоков и защит, `Qf/Ready/Fault` |
| `OpenPosnName`, `ClosePosnName`, `1DName`, `2DName`, `DirectName` | 20 | положения и направления |

Сверь таблицу с `Types/`: если версия библиотеки другая, приоритет у `Types/`.

### Интерфейсы FB

| FB | Интерлоки и защиты | Сигналы | Выходы |
| --- | --- | --- | --- |
| `Drive2DUnit` | `InterlockRunning1D/2D[0..3]`, `ProtectGeneral[0..3]` | `KM`, `Qf`, `Ready`, `Fault`, `Local.Pu.Start1D` | `Turn1D`, `Turn2D`, `Speed`, `Reset` |
| `OnOffUnit` | `InterlockRunning[0..1]`, `ProtectGeneral[0..1]` | `KM`, `Qf`, `Ready`, `Fault`, `Local.Pu.Start` | `Turn`, `Reset` |
| `ValveUnit` | `InterlockMovingToOpen/Close[0..1]` | `Sensor.Opened/Closed`, `Ready` (**нет** `Qf` и `Fault`) | `Open`, `Close`, `SPPosition` |

У `OnOffUnit` индексы только `[0..1]`: обращение к `[2]` и `[3]` не скомпилируется, даже если комментарии эталона говорят «интерлоки 0–3».

### Нумерация блоков

Подтверди по эталону, типичная схема:

| Блок | Номер |
| --- | --- |
| База группы `i` (с нуля, порядок как в Excel) | `1000 + 100·i` |
| `G_<агр>` (DB) и `FC_<агр>` | база + 1 (у DB и FC свои ряды номеров) |
| Механизмы `Units` | база + 11, +12, … |
| Датчики `AI` | база + 51, +52, … |

Если у группы больше 40 механизмов, номера пересекутся с `AI`: остановись и спроси, как нумеровать. Экземплярные DB выглядят одинаково: заголовок `{S7_BlockNumber, S7_Optimized := TRUE, S7_StandardRetain := FALSE, S7_Version := 0.1}` и строка `DATA_BLOCK <имя> : <тип>`.

### Ловушки эталона (не переносить)

- В REGION мешалки поля имени и сигналы `KM/Ready/Fault` заполнены для насоса, а не мешалки (копипаст).
- В комментариях насоса интерлоки 0–3, а массив `[0..1]`.
- Именование датчиков и групп неединообразно (`'Бак 31151A. LRCA_314511'` против `'31151А. Бак …'` с кириллической «А»).
- Вторая группа может быть пустым LAD-блоком, а не SCL по шаблону.
- Репозиторий хранит LF, хотя TIA выгружает CRLF.

## Шаг 2. Разбор Excel и классификация

Сначала посмотри листы и колонки. Лист-справочник (расшифровка префиксов) может использовать **другую систему префиксов**, чем рабочий лист и проект: классифицируй по фактическим префиксам позиций, а не по справочнику.

### Классификация по префиксу позиции

| Префикс | Пример | Что это | Блок |
| --- | --- | --- | --- |
| `SIRCA` | `SIRCA_31151A` | Мешалка с ЧРП | `Drive2DUnit` в `Units/` |
| `NCSA` | `NCSA_3115.11A` | Насос | `OnOffUnit` в `Units/` |
| `LVSA`, `TVSA`, `AVSA`, `HVSA` | `LVSA 316511` | Кран с ЭП, в т.ч. 3-ходовой `AVSA` | `ValveUnit` в `Units/` |
| `LRCA`, `PRCA`, `TRCA`, `ARCSA` | `LRCA_314511` | Уровень, давление, температура, мутность | `AnalogInput` в `AI/` |
| `H_` | `H_318511` | Локальный пульт | блока нет, сигналы идут в `Local.*` механизма |
| `HL_` | `HL_318518` | Светосигнальная колонна | блока нет |
| `FSA`, `LZA` | `FSA_313511` | Реле протока, реле уровня | блока нет, только DI |

Неизвестный префикс (`ABPosn`, `G120` и т.п.) не угадывай: пропусти и внеси в список «пропущенных» в отчёте.

### Правила

- **Пульт `H_`** в Excel отдельная строка без связи с механизмом. Привязывай его к ближайшему предыдущему `Drive2D` или `OnOff` в таблице.
- **Группа** = агрегат (значение колонки «Агрегат»); порядок групп как в Excel.
- **Нормализация имён:** пробелы в позициях → `_` (`LVSA 316511` → `LVSA_316511`). Имена DB в SCL всегда в двойных кавычках (`"NCSA_3115.11A".Settings.Name`): безопасно для точки, дефиса и спецсимволов.
- Колонку «Группа автоматики», если она есть, учитывай; колонки статуса («Юнит создан», «Группа подключена») при желании заполняй.

### Именование (`Settings.Name`, всегда с проверкой длины)

| Объект | Шаблон | Пример |
| --- | --- | --- |
| Папка группы | `<база>. <тип> <агрегат>` без объёма | `1200. Отстойник 31161` |
| Группа | `'<агрегат>. <тип>'` | `'31351. Насосы центробежные'` |
| Механизм | `'<номер>. <название>'`; если >30 — без «с ЭП»; если всё ещё >30 — `'<номер>. Кран'` | `'316521. Задвижка'` |
| Датчик | `'<позиция>. <параметр>'` | `'LRCA_314511. Уровень'` |

Полное наименование из Excel не теряй: оно идёт в заголовок `REGION` в FC и в комментарий.

## Шаг 3. Привязка сигналов DI/DO

В `DI.s7dcl`/`DO.s7dcl` имена имеют вид `+<агрегат>-<позиция>_<сигнал>`, например `"DI"."-DI7"."+31351A-NCSA_31351A_Run"`.

Привязывай по порядку:

1. **Точное совпадение** суффикса `-<имя>_<сигнал>`.
2. **Нечёткое совпадение по номеру позиции**, обязательно с предупреждением в отчёте. В DI бывают опечатки (`LRCA_316571_Opened` вместо `LVSA_316571_Opened`), точный поиск их теряет.
3. **Заглушка:** выходы → `"___testbool___"`, входы → `FALSE`. Сигнал попадает в список заглушек отчёта.

Особые случаи: у мешалок на Modbus RTU нет `Run/Fault` в DI → `FALSE`. У `ValveUnit` нет `Qf` и `Fault`.

### Сверка Excel ↔ DI в обе стороны

Обязательно выведи расхождения:

- группы и позиции, которые есть в DI, но нет в Excel (так нашлась пропущенная группа 31331);
- позиции Excel без сигналов в DI;
- похожие имена (опечатки вроде `SIRCA_31141` при номере агрегата 31341);
- неодинаковое написание (`HL_318518` в Excel и `HL318518` в DO).

Расхождения **не исправляй молча**: обработай осторожно (не создавай блок или привяжи с предупреждением) и перечисли в отчёте, решение остаётся за пользователем.

## Шаг 4. Генерация файлов

### Скрипт

Если в папке навыка есть `scripts/generate_skeleton.py`, **запусти его, затем доработай под задачу**, а не пиши заново: это воспроизводимо и экономит токены.

```bash
python3 scripts/generate_skeleton.py \
  --workspace . --ref "1. PLC_315" --target "2. PLC_316" \
  --excel "<таблица>.xlsx" --eol lf --report report.md
```

| Параметр | Значение |
| --- | --- |
| `--workspace` | корень рабочей области VCI |
| `--ref`, `--target` | папки эталона и целевого ПЛК |
| `--excel`, `--sheet` | таблица и лист (по умолчанию первый, кроме справочника) |
| `--eol` | `lf` или `crlf`, по шагу 0 |
| `--report` | куда записать Markdown-отчёт |

Скрипт возвращает код 1, если валидация нашла ошибки. Если скрипта нет, напиши его по алгоритму ниже (нужен `openpyxl`).

### Алгоритм

1. Скопируй из эталона `PLC data types/`, `PLC tags/`, папки `Program blocks/0.*`, `1.*`, `10.*`, `20.*` (если у целевого нет своих DI/DO, см. шаг 0).
2. Разбери `DI`/`DO` целевого ПЛК в словарь `+<агрегат>-<позиция>_<сигнал>` → путь `"DI"."-DIn"."…"`.
3. Прочитай Excel, присвой классы, привяжи пульты.
4. Для каждой группы запиши `G_<агр>.s7dcl`, `Units/*.s7dcl`, `AI/*.s7dcl`, `FC_<агр>.s7dcl`, `FC_<агр>.s7res`.
5. Привяжи сигналы (шаг 3).
6. Перезапиши `Main.s7dcl` (OB1, SCL) с вызовами всех `"FC_<агр>"()`.
7. Нормализуй BOM и окончания строк, выполни валидацию, сформируй отчёт.

### Шаблон FC группы (SCL, четыре сети)

Заголовки сетей берутся из `.s7res` по идентификаторам MLC эталона.

1. **Группа:** при `Hmi.Initialization_Settings` задай `Settings.Name`, `UNIT_UB` (= число механизмов группы), `AUTOMATIC_UB := 1`, `StopAutomatic_* := FALSE`; затем вызов `G(LampPulse, Notice)`.
2. **AI:** при `Initialization_AI` задай имена датчиков; вызов `AI(PeripheralValue := 0, AckFault := G.ToUnit.ResetFault)` с комментарием `// TODO`.
3. **Механизмы:** тексты при `Initialization_Text` (имя, пустые `Reason` интерлоков и защит, у моторов `Qf.Reason`); затем REGION на каждый механизм.
4. **Автоматика:** пустая, как в эталоне.

Пример REGION механизма:

```text
REGION Насос 31351A
    "NCSA_31351A".InterlockRunning[0].Active := FALSE;
    "NCSA_31351A".ProtectGeneral[0].Active := FALSE;
    REGION H_318592. Пульт локального управления
        "NCSA_31351A".Local.Key := NOT "DI"."-DI3"."+31351A-H_318592_Remote";
        "NCSA_31351A".Local.Pu.Start := "DI"."-DI3"."+31351A-H_318592_Start";
        "NCSA_31351A".Local.Pu.Basic.Stop := "DI"."-DI3"."+31351A-H_318592_Stop";
    END_REGION
    "NCSA_31351A".KM := "DI"."-DI7"."+31351A-NCSA_31351A_Run";
    "NCSA_31351A".Fault.Active := "DI"."-DI7"."+31351A-NCSA_31351A_Fault";
    "NCSA_31351A"(Group := "G_31351".ToUnit, Notice := "Notice");
    "___testbool___" := "NCSA_31351A".Turn;
END_REGION
```

### Правила формата

- **Кодировка:** UTF-8 с BOM (`utf-8-sig`) для `.s7dcl`, `.s7res`, `.liblink`, `.xml`.
- **Окончания строк:** в git сохраняй так, как репозиторий хранит файлы (обычно LF, см. `git ls-files --eol`); **CRLF — только в ZIP для импорта в TIA** (или при `core.autocrlf=true`). Принудительный CRLF в репозитории даст diff на каждой строке.
- **`.s7res`:** создавай только там, где он есть в эталоне (обычно только для FC групп; у экземплярных DB его нет). Язык бери из `WorkspaceLanguage`: в эталоне может быть только `en-US` с русским текстом, тогда `ru-RU` не добавляй.
- **`Hmi.s7dcl`:** обновляй размерность массива групп **только если такой массив существует**; в эталоне его может не быть, тогда копируй файл без изменений.
- **Длины строк:** для каждого строкового поля `assert len(text) <= max_len` при генерации.
- **Общие блоки:** недостающие `.liblink` копируй в `PLC data types/` и `Program blocks/0.*`.

## Шаг 5. Валидация (перед выдачей)

Скрипт должен проверять, а при ручной работе проверь сам:

| Проверка | Как |
| --- | --- |
| BOM | каждый `.s7dcl`/`.s7res` начинается с `EF BB BF` |
| Окончания строк | при `crlf` нет одиночных `\n`, при `lf` нет `\r\n` |
| Длины строк | каждое `.Name := WSTRING#'…'` ≤ 30, `.Reason` ≤ 70 (регулярным выражением по всем файлам) |
| Имена DB | каждый вызов `"X"(` и обращение `"X".` в `FC_*` и `Main` соответствует файлу `X.s7dcl` |
| Номера блоков | нет повторов среди DB и среди FC по отдельности |
| `UNIT_UB` | равен числу механизмов группы |
| Индексы интерлоков | в `OnOffUnit` нет `[2]`/`[3]`; для `ValveUnit` нет `Qf`/`Fault` |

Отдельно перечисли в отчёте: заглушки по позициям, предупреждения о нечётком совпадении, расхождения Excel ↔ DI, пропущенные позиции.

## Шаг 6. Выдача и импорт

Выдай пользователю: ZIP с папкой целевого ПЛК (CRLF + BOM), Markdown-отчёт, при работе с git ещё и ветку.

**Git и push.** Сгенерированное клади в отдельную ветку (`feature/<plc>-skeleton`), `master` не трогай. Если `git push` вернул 403, не трать попытки на PAT в URL: прокси облачной сессии пропускает запись только через GitHub-коннектор. Сразу создай `git bundle create <имя>.bundle <ветка> ^<базовый_коммит>` и передай пользователю с командами:

```bash
git fetch <имя>.bundle <ветка>:<ветка>
git push origin <ветка>
```

Подскажи подключить GitHub-коннектор (claude.ai → Settings → Connectors → GitHub). Если пользователь прислал токен открытым текстом, напомни его отозвать и не записывай токен в файлы и отчёты.

**Импорт в TIA Portal:**

1. Распакуй ZIP поверх папки целевого ПЛК в рабочей области VCI.
2. TIA Portal → Version Control Interface → Workspace → **Synchronize**, направление **Workspace → Project**.
3. Compile → Software с **полной пересборкой** (rebuild all) и разбор ошибок.

Скажи прямо: текстовая валидация не заменяет компиляцию; проект ещё не компилировался в TIA, пока пользователь этого не сделал.

### Что проверить перед импортом

- Проект целевого ПЛК использует ту же версию глобальной библиотеки (`.liblink` ссылаются на GUID).
- Clock memory и системные биты в свойствах CPU настроены как в эталоне (таблица тегов скопирована).
- Карты DI/DO соответствуют аппаратной конфигурации целевого ПЛК.
- В проекте нет блоков с номерами сгенерированного диапазона.
- Выходы на `"___testbool___"` распределены до пусконаладки: несколько механизмов пишут в один бит, интерлоки и защиты пусты, механизмы работают без блокировок.

## Известные ограничения генератора

- Классификация по префиксу захардкожена.
- Повторный запуск перезаписывает FC целевого ПЛК: ручная логика будет потеряна. Перед повторным запуском предупреди об этом или предложи режим «не трогать существующие FC».
- Адреса каналов AI берутся как `PeripheralValue := 0`, пока в Excel нет колонки адресов.
- Нет проверки дублирования записи в один выход из разных FC.
